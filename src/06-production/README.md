# 6장. 프로덕션으로 가는 길

> 1~5장은 모델을 **만드는** 법이었어요.
> 이 장은 만든 모델을 **서비스로 내놓는** 법입니다.
>
> 솔직히 말씀드리면, 노트북 안에서 학습 끝낸 모델이 **사용자에게 도달하기까지의 거리**가 모델을 만드는 것보다 훨씬 멉니다.
> 회사에서 ML 엔지니어 일의 80%는 이 거리를 좁히는 일이에요.

## 이 장은 누구를 위한 것인가요?

이 장은 **현업에서 모델을 운영하실 분**을 위한 글이에요. 학습 목적으로만 ML을 배우신다면 이 장은 가볍게 훑고 넘어가셔도 됩니다.

다만 다음 중 하나라도 해당하시면 **꼭 보세요.**

- 회사에서 ML 모델 만드는 일을 하시거나 하실 예정
- 본인 사이드 프로젝트로 만든 모델을 배포하고 싶음
- ML 엔지니어 면접을 준비 중
- 단순히 "모델을 어떻게 서비스로 만드는가"가 궁금함

---

## 이 장을 끝내면

- ✅ 학습된 모델과 운영용 모델의 차이를 안다
- ✅ 모델을 안전하게 저장하고 버전을 관리할 수 있다
- ✅ FastAPI로 모델 서빙 API를 만들 수 있다
- ✅ Docker로 모델을 패키징할 수 있다
- ✅ 배포된 모델의 성능 모니터링 계획을 세울 수 있다
- ✅ MLOps의 큰 그림을 이해한다 (실제 도구는 회사마다 다름)

핵심은 "학습 코드"와 "서비스 코드"를 분리하고, 그 사이를 모델 번들(`pipeline.pkl`, `metadata.json`)로 연결하는 것입니다.

## 운영 전 최소 체크리스트

- 모델 파일 버전과 API 버전이 일치하는가
- 입력 스키마(Pydantic)와 실제 학습 피처 순서가 일치하는가
- `/health`와 `/info` 같은 운영 점검 엔드포인트가 준비되어 있는가
- 배치 요청 상한/예외 처리/로그 포맷이 정의되어 있는가
- 테스트 스크립트로 단건/배치/오류 요청이 모두 검증되었는가

이 5가지를 습관화하면 "돌아가는 데모"에서 "운영 가능한 서비스"로 가는 속도가 크게 빨라집니다.
